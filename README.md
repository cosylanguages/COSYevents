# COSYevents 🎭 Calendar & Event Hub

**COSYevents** serves as the public calendar, event directory, and interactive session repository for the **COSYlanguages** ecosystem. It hosts live calendar schedules, speaking club prompt decks, cinema immersion guides, teacher-led masterclasses, multimedia nights, and event archives.

---

## 🎯 Purpose & Public vs. Gated Access Model

COSYevents maintains a strict boundary between public marketing/discovery data and gated session material:

- **Public Data:**
  - The main page (`index.html`) and public event listings read exclusively from `public-events.json` (generated by `scripts/build-public.js`).
  - Public listings include **ONLY** basic event and session metadata: title, theme, date, and language.
  - Public outputs **NEVER** expose gated content (session activities, instructions, content, vocabulary, or hosts).

- **Gated Session Content:**
  - Full session structures—including detailed activities, facilitator instructions, secret prompts, and vocabulary lists—are stored within session JSON files (`events/<event-slug>/sessions/<session-slug>.json`).
  - Access to gated content is restricted to session hosts and paying students.

## 📁 Repository Structure

```text
COSYevents/
├── events/
│   └── <event-slug>/
│       ├── event.json                # Event definition
│       └── sessions/
│           └── <session-slug>.json   # Gated session content & activities
├── schemas/
│   ├── event.schema.json             # JSON Schema for event.json
│   └── session.schema.json           # JSON Schema for session.json
├── scripts/
│   ├── validate-events.js            # Schema and slug consistency validator
│   ├── build-public.js               # Generates public-events.json (public metadata only)
│   └── test-no-leak.js               # Test ensuring no gated content leaks to public output
├── index.html                        # Main public landing page
├── public-events.json                # Generated public JSON artifact
├── package.json                      # NPM dependencies and scripts
└── .github/workflows/
    └── ci.yml                        # GitHub Actions CI workflow for PRs
```

## ➕ How to Add an Event or Session

### 1. Adding an Event
Create a directory under `events/<event-slug>/` with an `event.json` file matching the structure defined in `schemas/event.schema.json`:

```json
{
  "slug": "english-a2-foundations",
  "title": "English A2 Foundations",
  "description": "Interactive foundation event focusing on practical everyday English conversation.",
  "languages": ["English"],
  "status": "current"
}
```

*Note: `slug` must match the directory name, and `status` must be one of `"upcoming"`, `"current"`, or `"past"`.*

### 2. Adding a Session
Create a JSON file under `events/<event-slug>/sessions/<session-slug>.json` adhering to `schemas/session.schema.json`:

```json
{
  "slug": "daily-routines-and-habits",
  "event": "english-a2-foundations",
  "title": "Daily Routines and Habits",
  "theme": "Everyday Life",
  "language": "English",
  "level": "A2",
  "date": "2025-05-10",
  "host": "COSY Facilitator",
  "summary": "Practice talking about morning routines using present tense.",
  "activities": [
    {
      "type": "icebreaker",
      "title": "Morning Routine Check-in",
      "instructions": "Describe three things you do every morning.",
      "content": "Secret prompt details..."
    }
  ],
  "vocabulary": [
    {
      "word": "commute",
      "translation": "trajet quotidien",
      "example": "My daily commute takes 30 minutes.",
      "level": "A2"
    }
  ]
}
```

*Note: `slug` must match the filename without extension, `event` must reference a valid event slug, and `level` must be a valid CEFR grade (`A1`, `A2`, `B1`, `B2`, `C1`, `C2`).*

## 🛠️ CLI Commands & Testing

- **Validate Schema & Slugs:**
  ```bash
  npm run validate
  ```
  Validates all `event.json` and session `.json` files against JSON Schemas, checks unique event/session slugs, verifies directory/filename alignment, and checks CEFR levels.

- **Build Public Output:**
  ```bash
  npm run build-public
  ```
  Generates `public-events.json` containing only public title, theme, date, and language metadata.

- **Run Leak Test:**
  ```bash
  npm run test
  ```
  Executes `scripts/test-no-leak.js` to build `public-events.json` and assert that no session activities or vocabulary text appear in the public artifact.
